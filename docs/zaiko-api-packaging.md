# 【改修依頼】品目単位の在庫調整API（小分け入力の連携用）

- 依頼元: みそ熟成・仕込み計画管理システム（miso-system）
- 依頼先: zaiko.mitsuura.jp 開発者
- 依頼日: 2026-09-10
- 前提: 在庫調整API（`/api/stock/adjust`）・レシピ連動（`applyRecipe`）・プレビューAPIは対応済み。ありがとうございます

---

## 背景

業務用の小分けみそ（バラ → 1kg袋・2K桶・20K桶 など）の在庫登録を、
現在は現場スタッフが zaiko の在庫管理画面から手入力しています。

ただ、PCに不慣れな作業員には画面の情報量が多く、入力までの操作も多いため、
**入力されないことが増えてきました**。

そこで熟成管理システム側に「品名→容量→個数」の3クリックだけで終わる
**現場専用の入力画面**（現場のPCで使用）を作り、そこから zaiko へ自動転記したいと考えています。

なお **原材料の減算はこちらでは一切計算しません**。zaiko の在庫登録モーダル「加算＋」タブと
まったく同じく、品目に登録されたレシピの連動で減らしてください（両方で引くと二重計上になるため）。

参考：現在の手入力での挙動（`田舎みそ（ｽﾘ）20K桶入 (800895)` を 10丁 加算した場合）

```
田舎みそ（熟成済）                      2,346 −200  → 2,146 kg
アルコール無変性（ドラム）200L            240 −10   → 230 リットル
【シート】20kg LLDPE片シート 400×410   13,883 −10   → 13,873 枚
【掛け紙】半晒クラフト75.5（20kg用）     1,292 −10   → 1,282 枚
```

API経由でもこれと同一の結果になることが要件です。

## 何が足りないか

既存の在庫調整API（`/api/stock/adjust`）は `misoType` ＋ `category`（`wip`/`aged`）の
2区分しか受け取れないため、**「田舎みそ（ｽﾘ）2K桶入」のような個別品目を指定できません**。

品目を直接指定できる在庫調整APIを1本追加してください。

## 依頼内容

### ① 品目単位の在庫調整API（必須）

```
POST ${STOCK_ITEM_ADJUST_API_URL}
X-API-Key: （既存の EXTERNAL_API_KEY を共用）
Content-Type: application/json

{
  "itemCode":       "800895",         // 品目コード（モーダル見出しの括弧内の番号）
  "location":       "調味料工場倉庫", // 在庫登録モーダルのロケーション行に対応
  "delta":          10,               // 正=加算＋、負=減算−。単位は品目の在庫単位（丁・個・KG）
  "applyRecipe":    true,             // ＝「在庫のみ変更（レシピ連動なし）」のチェックを外した状態
  "expiryDate":     "2027-09-10",     // 任意。新ロット入庫時の賞味期限（モーダルの同名欄）
  "occurredAt":     "2026-09-10",     // 作業日
  "operator":       "村上",           // 入力者名（備考に残す用）
  "requestId":      "a1b2c3d4-...",   // 冪等キー。後述
  "notes":          "小分け入力（熟成管理システム）"
}
```

- `itemCode` は在庫登録モーダルの見出しに出ている番号（例: `田舎みそ（ｽﾘ）20K桶入 (800895)` の
  `800895`）を想定しています。**品名ではなくこのコードで指定させてください**（品名の改名で
  連携が切れないようにするため）。これで指定できない場合はご指摘ください
- `location` は **常に「調味料工場倉庫」固定**で送ります（現場の小分けはここにしか登録しないため、
  入力画面でも選ばせません）。他ロケーションへの登録は従来どおり zaiko の画面で行います

- **`applyRecipe: true` は必須要件です。** 手入力での在庫登録と完全に同じ挙動
  （バラの減算・容器・キャップ等の連動）にしてください。ここが手入力と食い違うと
  現場の数字が合わなくなり、この画面を作る意味が無くなります
- レスポンスは既存の在庫調整APIと同じ形式で、可能であれば
  `stockBefore` / `stockAfter` と `consumedMaterials[]`（モーダルの「原材料消費」欄と同じ
  前後値）を返してください。入力直後に「田舎みそ（熟成済）2,346 → 2,146 kg」と現場へ
  返せると、入力ミスにその場で気づけます

### ② 冪等キー `requestId`（必須）

工場のネットワークが不安定なため、**送信が成功したのにレスポンスが返らない**ケースが起きます。
その場合こちらは自動で再送するので、**同じ `requestId` の2回目以降は在庫を動かさず、
1回目と同じレスポンスを返して**ください（重複登録の防止）。

保持期間は7日もあれば十分です。

### ③ 品目一覧＋在庫数API

```
GET ${ITEM_STOCK_API_URL}?category=業務用調味料&location=調味料工場倉庫
X-API-Key: ...

[
  { "itemCode": "800895", "itemName": "田舎みそ（ｽﾘ）20K桶入",
    "unit": "丁", "kgPerUnit": 20, "misoType": "田舎みそ",
    "stock": 12, "location": "調味料工場倉庫", "isActive": true },
  ...
]
```

用途は2つあります。

- **`stock`（在庫数）**: 入力画面の各品目に「在庫 12丁」と出し、入力すると
  「12丁 → 22丁」と変化を見せるために使います。**現場から「今いくつあるか見たい」と
  要望が出ているので、これが本命です。** 既存の熟成済在庫API（`STOCK_API_URL`）は
  品種ごとの合計kgしか返さないため、「20K桶が今いくつあるか」は分かりません
- **品目一覧そのもの**: 入力画面のボタンを自動生成するために使います。無ければこちら側で
  品目コードと品名をハードコードしますが、その場合 zaiko で品目を追加・改名するたびに
  こちらの改修が必要になります

在庫数だけ別エンドポイントにしていただいても構いません（こちらは `ITEM_STOCK_API_URL`
の1本を読むだけです）。`location` は「調味料工場倉庫」ぶんが返れば足ります。
実装済みなので、URLをいただければ環境変数に設定するだけで表示が有効になります
（未設定の間は在庫欄を出しません）。

## 対象品目（現時点）

zaiko の「みそ（大道工場出荷場）」お気に入り 33 件のうち、小分け作業の対象になるもの：

| 品種 | 品目 |
|---|---|
| 田舎みそ（ｽﾘ） | バラ / 1kg / 2K桶入 / 4K桶入 / 8K桶入 / 10K桶入 / 20K桶入 |
| 田舎みそ（粒） | バラ / 2kg袋入 / 20K桶入 |
| 山吹みそ | バラ / 4K桶入 / 8K桶入 / 10K桶入 / 20K桶入 |
| 無添加 麦みそ | バラ / 10K桶入 |
| 合せみそ | バラ / 20K桶入 |

※ 取引先別品目（重枝醤油向けなど）を含めるかは運用側で調整します

## 呼び出しタイミング

現場スタッフが小分け作業を終えて入力画面で「記録」を押したとき、1件につき1回。
取り消し（直近の入力を打ち消す）のときは同じ品目に `delta` を負で1回。
1日あたり数件〜十数件程度を見込んでいます。

## 補足

- テスト用のエンドポイント（本番在庫を動かさないもの）か、テスト品目を
  1つご用意いただけると、こちらでの動作確認が安全に進められます
- 既存のプレビューAPI（`/api/stock/adjust/preview`）と同様に、
  品目単位のプレビューもあると入力前の確認に使えますが、必須ではありません
